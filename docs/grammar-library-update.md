# Repository grammar library — 3 September 2026

## Install

This is an incremental update to the current Japanese-Study-Dashboard baseline, including the previous grammar-links update. Keep the existing `index.html`, `grammar-guides.js`, exporter, curriculum, authentication and hosting configuration.

1. Back up the repository and your Supabase data.
2. In Supabase SQL Editor, run the separately supplied `migrations/20260903_repository_grammar_library.sql`. It requires the existing `20260830_japanese_repository.sql` migration. Do not rerun the base application schema.
3. Apply the changed-files ZIP at the repository root: `repository.js`, `styles.css`, the new tests, this guide and the example JSON.
4. Deploy using your existing Netlify workflow, then reload the app and sign in.
5. Import `examples/repository-grammar-import.json`, click Preview, then Import entries. Open the sentence and click its grammar chip.

No production database migration, commit, push or deployment was performed while preparing this update. The website-development guidance was used for persistence and validation; your Netlify/Supabase architecture is unchanged.

## Changelog

- Added private, database-backed grammar guides and explicit sentence-to-guide links.
- Added optional structured `grammar_explanations` without changing existing sentence fields or removing legacy JSON support.
- Import creates a guide once per user, normalized label and meaning ID (`sense`). Later imports reuse it.
- Different meanings may share a label but must have different sense IDs. Matching is deterministic, not AI semantic matching: alternate labels/IDs are not automatically recognized as synonyms.
- Different content for an existing identity requires choosing “Use the saved explanation.” The existing content is never overwritten. Within a batch, the first explanation plays the same role.
- Enriched imports save all sentences, guides and links in one transaction. An error rolls back that whole import.
- Grammar pages display formation, explanation and examples, with an AI-generated/unverified notice.
- Labels without a saved meaning link do not automatically select a database guide, even if only one exists. They offer an explicit reading choice. That choice is not saved; re-import with structured explanations to save a meaning link. Built-in guides remain a fallback where no saved guide matches the label.
- Preview reports missing furigana, missing grammar explanations and ignored field names. Mismatched furigana and malformed grammar explanations block import.
- Editing the JSON invalidates its preview. Repeat clicks cannot submit the same in-flight request twice.
- If the new migration has not been applied, existing sentences and plain JSON imports remain usable; enriched imports show a migration message.
- Editing grammar labels removes obsolete saved links. Deleting a sentence removes its links but keeps reusable guides.
- No changes to SRS, Anki/Migaku exports, lesson order, correction history or existing v1.0 tables.

## JSON contract

Import accepts one object or an array of 1–100 objects (maximum 2 MB). Continue using the existing sentence fields. `japanese` is required. `grammar` and `source` are not aliases: use `grammar_points`, `source_type` and `source_detail`.

| Field | Format | Behavior |
| --- | --- | --- |
| `japanese` | Plain Japanese string | Required sentence text |
| `japanese_furigana` | String with `[漢字|かんじ]` notation | Removing annotations must reproduce `japanese` exactly |
| `english` | String | Sentence translation |
| `grammar_points` | Array of strings | Clickable grammar labels |
| `grammar_explanations` | Optional array of objects below | Creates/reuses guides and saves exact meaning links |
| `explanation` | String | Sentence-specific explanation, separate from reusable grammar teaching |
| `register`, `tags`, `status`, source fields, correction fields | Existing formats | Unchanged |

Each grammar explanation has these exact keys:

| Key | Requirement |
| --- | --- |
| `label` | Non-empty string, exactly one of the entry's `grammar_points` |
| `sense` | Stable lowercase English ID, e.g. `expressing-an-opinion`; lowercase letters, digits and single separating hyphens, maximum 100 characters |
| `meaning` | Non-empty short meaning in English |
| `formation` | Non-empty array of formation-rule strings |
| `explanation` | Non-empty reusable explanation, including relevant nuance/restrictions |
| `examples` | Non-empty array of `{japanese, japanese_furigana, english}` objects |

Supply only one explanation per label in each sentence. Example `japanese` and `english` are required; missing example furigana is allowed with a warning. Unknown explanation/example fields are rejected rather than silently discarded. HTML is treated as text. Readings are imported, not generated by the app.

Reuse the same `label` and `sense` for the same meaning in future translations. Use a distinct sense only for a genuinely different meaning, not to bypass a wording conflict. Existing explanations are append-only in this version; editing/merging the guide library is not included.

The app does not determine whether an explanation is linguistically correct. Imported explanations are explicitly unverified. There are no OpenAI API calls, and this update does not change ChatGPT Project instructions; that is the next step.

## Smoke-test checklist

- [ ] Apply the new SQL separately; verify the migration succeeds. It may safely be rerun.
- [ ] Import the example JSON. Preview shows one new guide, no warnings and no conflicts.
- [ ] Open the sentence → grammar chip. Confirm meaning, formation, explanation, example and “AI-generated · Unverified” appear.
- [ ] Toggle furigana on/off in the grammar page, then return to the sentence. Reload: the guide and sentence link remain.
- [ ] Import another sentence using the exact same explanation and sense: preview reports reuse and the same guide is linked.
- [ ] Change the explanation text but keep the identity: Import stays disabled until you explicitly choose the saved explanation. Its existing content does not change.
- [ ] Try two different explanations for the same identity in one JSON array: the second needs confirmation to use the first.
- [ ] Try a genuinely different meaning with a distinct sense: it creates a separate guide, and each sentence opens its own linked meaning.
- [ ] Import legacy JSON with no `grammar_explanations`: sentence import works and missing-guide warnings are visible.
- [ ] Remove `japanese_furigana`: preview warns but allows import. Supply mismatched readings: preview blocks import.
- [ ] Edit JSON after Preview: Import is disabled until Preview runs again.
- [ ] Test invalid grammar fields and confirm no partial sentences/guides appear.
- [ ] Open an older sentence with an unlinked label shared by saved guides: choose the intended meaning rather than receiving an automatic match.
- [ ] Edit a sentence's grammar labels: obsolete links disappear. Delete a test sentence: its guide stays available.
- [ ] Check ordinary sentence capture/edit, correction history, filters, Anki/TSV export and lesson navigation still work.

Repeated imports intentionally create new sentence entries; only grammar guides are deduplicated. After a connection failure, reload and check saved entries before retrying, because the server might have completed the import without the browser receiving the response. No automatic retry is performed.

## Automated validation

Passed locally:

```sh
node --check repository.js
node tests/lesson-flow.test.cjs
node tests/repository-grammar.test.cjs
node tests/repository-grammar-import.test.cjs
node tests/repository-grammar-sql.test.cjs
```

The SQL test uses an isolated PostgreSQL-compatible PGlite database, mocked Supabase roles and `auth.uid()`, and the real migration. It checks create/reuse, batch rollback, conflicts, different senses, ownership, RLS, linked-data cleanup, append-only permissions, anonymous denial and migration reruns. It does not contact your Supabase project. Browser and live Netlify/Supabase smoke tests remain manual.

For the SQL test only, install `@electric-sql/pglite` into `/tmp/jlh-grammar-test`, or set `PGLITE_MODULE` to another installation. This is not an application dependency and is not shipped to Netlify.

Database design references: [PostgreSQL function execution privileges](https://www.postgresql.org/docs/current/sql-createfunction.html), [transaction atomicity](https://www.postgresql.org/docs/current/tutorial-transactions.html), and [text normalization](https://www.postgresql.org/docs/current/functions-string.html).

## Rollback

Restore the previous `repository.js` and `styles.css` from your backup to revert the UI. Leave the additive database tables and migration in place so imported guides are preserved; the previous UI ignores them. Do not drop tables as part of an ordinary rollback.
